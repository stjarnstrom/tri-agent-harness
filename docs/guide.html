Field guide

One prompt in. A tested, graded product out.

The harness turns a short product prompt into a working app by separating creation from judgment: one agent plans, one builds, one grades the running app with a skeptical eye — and a fourth distills every failure into lessons, so each run starts smarter than the last.

The machine

Four agents, one circuit

Every sprint travels the same circuit. The Generator never has final say on its own work: a mechanical gate checks lints and artifacts, then the Evaluator tests the live app and grades it against rubrics. Fail, and the work goes back — up to three rounds per sprint.

The crew

Who does what

Each agent runs in its own isolated context and communicates only through files in docs/ — the Evaluator never sees the Generator's self-justification, only what landed on disk. Models are matched to the job: big-picture reasoning on Fable, implementation volume on Sonnet.

Planner

claude-fable-5

Expands your one-line prompt into a full spec, sprint plan, and status tracker. With no design brief, it first proposes three design directions and waits for your pick.

Generator

claude-sonnet-5

Builds one sprint at a time against a written contract. Every commit must pass the pre-commit hook: sandbox, lints, secret scan.

Evaluator

claude-fable-5

Starts the app and tests every acceptance criterion with Playwright, then grades six weighted criteria. Skeptical by instruction: “it mostly works” is a fail.

Retrospector

claude-fable-5

Runs once at the end of every run. Distills QA failures into generalized lessons and drafts guardrail proposals when a pattern strikes twice.

Phase 00

Quick start

Two commands to install the guardrails, one to start a build. State lives in docs/sprint-status.md, so resuming after any interruption is just re-running the same command. 

# one-time setup: git hooks, lints, sandbox
bun install && bun run setup

# start (or resume) an autonomous build
./harness.sh "Build a kanban app for film production crews"

# optional: allow up to 5 QA rounds per sprint
./harness.sh "..." 5

No design brief? The Planner pauses after writing three design directions to docs/design-options.md. Put your pick in design/selected-direction.md and re-run the same command. To skip the pause entirely, provide design/brief.md up front or run with HARNESS_YES=1.

Phase 01 → 03

Anatomy of a run

A first sprint typically takes 30–90 minutes wall-clock. The Evaluator is the slow part by design — it exercises real user flows in a real browser, not just element presence.

5–15 min

Planning

The Planner writes the spec, sprint plan, and status tracker, and fills CLAUDE.md with the design language.

docs/spec.md · docs/sprint-plan.md · docs/sprint-status.md
10–30 min

Build (sprint N)

The Generator writes the sprint contract, implements it, commits through the pre-commit hook, and marks the sprint “Ready for QA”.

docs/sprint-N-contract.md · app code
1–5 min

Pre-QA gate

Deterministic checks — lints, required artifacts — before any expensive judgment. A gate failure returns to the Generator without consuming a QA round.

docs/mechanical-checks-sprint-N.md
15–45 min

Evaluation pass fail

Playwright testing of every acceptance criterion, six weighted scores with hard thresholds, and a written verdict. Fail sends the work back with an actionable bug list; pass advances to the next sprint.

docs/qa-report-sprint-N.md · sprint status updated
end of run

Retrospective

Whether the run completed or halted, the Retrospector mines every QA report for lesson candidates, updates the ledger, and regenerates LESSONS.md. Best-effort: it can never fail your run.

harness/lessons.jsonl · harness/LESSONS.md · docs/proposals/

On persistent failure the harness halts by default after the max QA rounds so you can review the report. Set HARNESS_ON_MAX_ROUNDS=advance to mark the sprint skipped and press on.

Two ways in

Autonomous or interactive

Autonomous — ./harness.sh

The default. Each phase runs as a separate claude -p process, fully hands-off until pass, halt, or a pause you configured (HARNESS_PAUSE=sprint asks before each sprint).

Same loop, other runners: ./cursor-harness.sh and ./opencode-harness.sh drive Cursor and OpenCode against the identical file contract.

Interactive — slash commands

Drive each phase yourself from a Claude Code session. Each command dispatches an isolated subagent, so the phases stay independent.

/project:plan expand the idea · /project:build implement the sprint · /project:qa grade it · /project:retro distill the lessons.

Agents hand off through files, never through conversation. That means the whole run is inspectable — and resumable — from these paths.

The return wire

How the harness learns

Every QA report ends with structured lesson candidates. The Retrospector merges them into a checked-in ledger, and a deterministic script renders the agent-facing harness/LESSONS.md — capped at 25 active lessons, so the prompt never bloats.

Fig. 2 — capture → distill → inject → escalate → graduate

# learning-loop toolbox
bun lessons:validate   # ledger + LESSONS.md consistency (also runs in pre-commit)
bun lessons:render     # regenerate LESSONS.md from the ledger
bun lessons:sync ~/path/to/template-repo   # merge a product clone's learning home

HARNESS_RETRO=off ./harness.sh "..."       # skip the retro phase

Guardrail proposals are the only human gate: review the draft in docs/proposals/, commit the rule if you agree, and mark the ledger entry graduated. The lesson leaves the prompt; the machine enforces it forever.

Controls

Everything is an environment variable on the harness command. The defaults are tuned for hands-off runs; these are the dials you'll actually reach for.

VariableDefaultWhat it does
HARNESS_PAUSEoffsprint asks before each sprint; phase before every agent; design after design-scout
HARNESS_MAX_SPRINTS_PER_RUNunlimitedStop cleanly after N sprints; re-run to resume
HARNESS_ON_MAX_ROUNDShaltadvance marks a stuck sprint Skipped and moves on
HARNESS_MODELper-phaseForce one model for every phase
HARNESS_*_MODELFable / SonnetPer-phase override: PLANNER, GENERATOR, EVALUATOR, RETRO
HARNESS_RETROonoff skips end-of-run learning
HARNESS_YES01 skips all pause prompts (fully autonomous)
HARNESS_USAGE_CHECK0Run a budget probe at sprint boundaries
